# Архітектура проєкту

Як побудований сайт «Hoi! Nederlands» і де шукати те, що треба змінити.

## Загальна картина

Односторінковий застосунок: `index.html` — порожня оболонка з `<div id="root">`,
уся розмітка будується на клієнті. Бекенду немає, весь контент лежить у
`src/data/` як звичайні TypeScript-модулі й потрапляє у бандл під час збірки.

```
src/main.tsx  →  createRoot(#root).render(<App />)
src/App.tsx   →  <SiteStateProvider> + 15 секцій + 6 діалогів
```

## Стек

- **React 19** + TypeScript
- **Vite** — збірка й сервер розробки
- **Tailwind CSS v4** (через `@tailwindcss/vite`)
- **Base UI** — безстильові примітиви для модальних вікон
- **lucide-react** — іконки
- `clsx` + `tailwind-merge` + `class-variance-authority` — склейка класів

## Стилі

Уся візуальна частина — авторський CSS у `src/styles/`, розбитий за
призначенням. Tailwind використовується лише в обгортках Base UI
(`src/components/ui/`), у самих секціях сайту утиліт немає.

Порядок імпортів у `src/styles/index.css` **має значення** — це каскад:

| # | Файл | Що містить |
|---|------|-----------|
| 0 | `tailwindcss` | шари Tailwind: properties, theme, base, utilities |
| 1 | `base.css` | токени в `:root`, скидання, хедер, hero, курси, кабінет, футер, адаптив |
| 2 | `hero.css` | градієнт hero і «скульптура» зі слів, перекриває `.hero` з `base.css` |
| 3 | `type-loop.css` | кільця з типографікою |
| 4 | `ribbon.css` | стрічка «NEDERLANDS» у hero |
| 5 | `ui.css` | кнопки, картки кроків, тести, форми, посилання футера |
| 6 | `dialog.css` | модальні вікна: розміри, прокрутка, кнопка закриття |
| 7 | `sections.css` | секції результатів, аудиторії, платформи, довіри, FAQ |
| 8 | `fonts.css` | `@font-face` для DM Sans і Fraunces + змінні шрифтів |

Дублікати селекторів між файлами — не помилка, а свідоме перекриття.
Якщо переставити імпорти, вигляд зміниться.

### Токени

Кольори, радіус і семантичні змінні — у `:root` у `base.css`:

```css
--ink: #141b3b;   --cream: #fffaf0;  --blue: #2457ff;
--coral: #ff5f4a; --pink: #ff85c8;   --lime: #c8f46a;
--radius: 1rem;
```

Шрифти підключені локальними `woff2` з `src/assets/fonts/`; Vite сам
проставляє хешовані шляхи під час збірки.

## Стан

Один контекст у `src/site-state.tsx` — `SiteStateProvider` + хук
`useSiteState()`. Тримає:

- `activeDialog` — яке з шести вікон відкрите (одночасно лише одне);
- `selectedCourse` — курс для діалогу купівлі;
- `savedWords` — збережені слова в demo-словнику;
- `openFaq` — розгорнуте питання;
- прогрес тесту: `activeTest`, `answers`, `submitted`, `expandedWhy`;
- урок для практики: `activeLesson`, `lessonNumber`, `practiceAnswer`;
- стан форм: `registered`, `trialReady`, `email`.

Похідні значення вважаються тут же: `correctCount`, `recommendedLevel`
(рівень за кількістю правильних відповідей), `progress`.

Стан не зберігається: перезавантаження сторінки скидає все.

## Модальні вікна

Усі шість — у `src/components/dialogs/`, побудовані на обгортках
`src/components/ui/dialog.tsx` (Base UI + класи в стилі shadcn).

| Компонент | Клас | Коли відкривається |
|-----------|------|--------------------|
| `CourseDialog` | `course-dialog` | клік на картку курсу |
| `TestDialog` | `test-dialog` | будь-яка кнопка «Визначити рівень» |
| `PracticeDialog` | `demo-dialog` | урок, крок навчання, «Спробувати вправу» |
| `LoginDialog` | `login-dialog` | «Мій кабінет», «Створити кабінет», «Обрати» |
| `ContactDialog` | `login-dialog` | «Познайомитися», «Підтримка», соцмережі |
| `TrialDialog` | `login-dialog trial-dialog` | «Отримати демодоступ» |

`TestDialog` має три кроки: вибір формату → питання → результат із розбором
кожної відповіді й рекомендованим рівнем.

`LoginDialog` і `TrialDialog` після сабміту показують другий стан
(«Твій кабінет» / «Демодоступ готовий») — без мережевих викликів.

## Чого немає

- **Мережі.** Ні `fetch`, ні API, ні токенів. Форми показують
  повідомлення й закриваються; кнопка оплати — заглушка з `alert`.
- **Збереження.** Ні `localStorage`, ні бази. Стан лише в пам'яті React.
- **Роутингу.** Навігація — якорі по секціях однієї сторінки.
- **Тестів.** Автоматичних перевірок у проєкті поки немає.

## Відомі місця для прибирання

### Класи Tailwind, які нічого не роблять

Обгортки в `src/components/ui/` прийшли з набору компонентів у стилі
shadcn і містять семантичні класи Tailwind — `bg-popover`,
`text-muted-foreground`, `font-heading`, `ring-foreground/10`.

У проєкті ці класи **нічого не роблять**: відповідні токени не оголошені в
`@theme`, тому Tailwind не генерує для них правил. Вигляд вікон повністю
задають авторські селектори `[data-slot=dialog-content]`, `.login-dialog`
та сусідні в `dialog.css` і `base.css`.

Якщо колись домапити ці токени в `@theme`, класи «оживуть» і вигляд
діалогів зміниться. Тобто це не мертвий код, а відкладена міна: прибирати
класи чи оголошувати токени — окреме рішення, яке варто приймати свідомо.

### Розсинхрон класу в digital-словнику

У `sections.css` є правило `.word-count` (відступ і жирний шрифт), але жоден
елемент його не використовує. Натомість рядок «Збережено слів» у
`Platform.tsx` має клас `dictionary-progress`, для якого правил немає —
тобто він показується успадкованим стилем.

Схоже, клас у розмітці колись перейменували, а CSS не оновили. Виправити
можна двома способами: перейменувати правило на `.dictionary-progress`
(тоді рядок отримає відступ і жирність) або видалити `.word-count` і
залишити як є. Перший варіант змінює вигляд, тому теж вимагає рішення.
